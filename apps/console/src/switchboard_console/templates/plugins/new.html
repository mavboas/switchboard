Como é um pacote

meu-plugin.zip
├── plugin.yaml            manifesto
├── skills/
│   └── politica-de-credito/
│       └── SKILL.md       playbook (Agent Skills)
└── knowledge/
    └── politica.md        documentos da base

O pacote nunca traz endereços nem tokens: o manifesto declara as chaves em config e quem instala informa os valores (segredos ficam cifrados, ou use env:NOME). Os componentes ganham o nome plugin.componente e só mudam com o plugin.

O manifesto (plugin.yaml)

{% raw %}
name: acme-credito
version: 1.0.0
description: Simulação e análise de crédito.
config:
  CREDITO_URL:
    description: Endereço do servidor MCP
  ANALISE_URL:
    description: Endereço do agente A2A
connectors:
  - name: credito
    url: ${config.CREDITO_URL}
    allowed_tools: [simular_financiamento]
agents:
  - name: analise-credito
    url: ${config.ANALISE_URL}
knowledge_bases:
  - name: politicas
    paths: [knowledge]
playbooks:
  - skill: politica-de-credito
    applies_to: [credito]
    triggers: [financiamento, parcela]
{% endraw %}

Também aceita o formato de plugin do Claude

Um pacote com .claude-plugin/plugin.json é importado: as skills viram playbooks e os servidores MCP remotos viram conectores (as variáveis viram configuração). Comandos, subagentes, hooks e servidores MCP locais não são importados, e cada parte deixada de fora aparece como achado: o router nunca executa código de plugin.
